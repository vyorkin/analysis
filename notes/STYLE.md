# Стиль конспекта

Параллельные заметки на русском к формализации Analysis I на Lean 4
(`analysis/*.lean`). Цель — дословное соответствие нумерации Тао и лёгкая
навигация между конспектом и Lean-кодом.

## Сборка

```
notes/build.sh
```

XeLaTeX (`latexmk -xelatex`). Не pdflatex — см. «Кириллица» ниже.

## Структура

```
notes/
  main.tex            — part/chapter, \include по разделам
  preamble.tex         — шрифты, окружения, макросы (см. комментарии внутри)
  Chapter_N/
    Section_N_M.tex    — один раздел Тао = один файл
```

Перед каждым `\include` в `main.tex` вручную выставляются `\setcounter{chapter}{N-1}`
и `\setcounter{section}{M-1}`, чтобы номер главы/раздела на странице совпадал
с текстом Тао (см. «Нумерация» ниже).

## Нумерация — дословно как у Тао

Окружения `axiom`/`theorem`/`proposition`/`lemma`/`corollary`/`definition`/
`example`/`exercise` берут номер **вручную**, первым аргументом:

```latex
\begin{axiom}{3.8}{универсальная спецификация}
...
\end{axiom}
```

Номер должен буквально совпадать с тем, что стоит в докстринге Lean-теоремы
(`Axiom 3.8`, `Proposition 3.4.9`, ...). Автонумерация здесь не подходит:
у Тао аксиомы нумеруются `Глава.N` (Axiom 3.8), а теоремы/леммы/... —
`Глава.Раздел.N` (Proposition 3.4.9) — единого сквозного счётчика для этого
нет, и вычислить его LaTeX не может.

Если у Тао утверждение **не пронумеровано** (приведено в прозе, как парадокс
Рассела) — используется звёздная версия без номера:
`\begin{theorem*}{парадокс Рассела} ... \end{theorem*}`.

## Ссылка на Lean

Внутри окружения, последней строкой перед `\end{...}`:

```latex
\leansource{axiom_of_universal_specification}
\leansource{SetTheory.Set.axiom_of_regularity}
```

Не экранировать `_` вручную — `\leanref`/`\leansource` сами разбираются с
подчёркиваниями (см. «Грабли» ниже). Не класть Lean-идентификатор в
заголовок окружения (`\begin{axiom}{3.8}{название, идентификатор}`) — там
мало места для переноса строки.

## Перенос строки в длинной сигнатуре

Если сигнатура в `\leansource{идентификатор}{...}` не помещается в одну
строку, автоматический перенос по ширине режет её где попало — посреди
скобок, посреди `∀`/`∧`-выражения. Вместо этого — вручную `\leanbreak` в
точке смыслового разрыва:

```latex
\leansource{SetTheory.Set.mem_union}{(x : Object) (X Y : Set)\leanbreak
  : x ∈ (X ∪ Y) ↔ (x ∈ X ∨ x ∈ Y)}
```

Главный приоритет: содержимое одной пары скобок `(...)` (одна гипотеза)
никогда не должно делиться на две строки, если этого можно избежать. Места,
где ставить `\leanbreak`:

- перед финальным `:`, отделяющим гипотезы от заключения (обычно лучший
  вариант — заключение уходит на свою строку целиком);
- сразу после имени теоремы, если у неё нет аргументов (сигнатура вида
  `identifier : ...`) — тогда это то же самое место, что и предыдущий пункт;
- сразу после имени теоремы — также если строка «имя + все гипотезы» целиком
  не помещается в одну строку. `\leanbreak` ставится сразу после
  `identifier`, и все гипотезы уходят на новую строку единым блоком (плюс
  обычный `\leanbreak` перед финальным `:`, если он тоже нужен). Так надёжнее,
  чем полагаться на автоперенос по ширине: тому всё равно, что резать, и он
  может располовинить как раз одну гипотезу (`(y :` / `Object)`):

```latex
\leansource{SetTheory.Set.replacement_axiom}{\leanbreak
  (hP : ∀ x y y', P x y ∧ P x y' → y = y') (y : Object)\leanbreak
  : y ∈ A.replace hP ↔ ∃ x, P x y}
```

```latex
\leansource{Nat.strong_induction}{\leanbreak
  (hind : ∀ m, m ≥ m₀ → (∀ m', m₀ ≤ m' ∧ m' < m → P m') → P m)\leanbreak
  : ∀ m, m ≥ m₀ → P m}
```

Если даже блок гипотез, вынесенный на свою строку, сам не помещается целиком
(разрыв всё равно неизбежен внутри него, как во втором примере выше, где
гипотеза одна и её больше некуда деть) — переносить по смысловой границе:
между гипотезами (`) (`, если их несколько) или, если гипотеза одна и сама
по себе длинная, перед логическим разрывом внутри неё (`→`, `∧`), а не там,
где попало по ширине строки.

`\leanbreak` — это `\\` (принудительный разрыв) плюс `\hspace*{2em}`, отступ
для перенесённой части. Обычный `\hangindent` (см. `\leansource` в
преамбуле) применяется только к автоматическому переносу по ширине строки —
к принудительному `\\` он не применяется, поэтому `\leanbreak`, а не голый
`\\`, восполняет отступ вручную тем же 2em.

## Длинные цепочки эквивалентностей в доказательстве

Если рассуждение — цепочка из трёх и более `\iff` (или `\implies`) подряд и
целиком не умещается в одну строку — выносить в `align*`, разрывая перед
каждым `\iff`, а не оставлять инлайн-формулой в абзаце. У автопереноса по
ширине строки нет понятия «скобочная группа» — он режет ровно там, где
формула упёрлась в правое поле, то есть посреди `(x \in A \land x \in B) \lor
(x \in$» — та же природа проблемы, что и с сигнатурами в `\leansource` (см.
«Перенос строки в длинной сигнатуре» выше), только здесь автоперенос вообще
не предусмотрен: голый `\[...\]` не переносит строки сам, а просто вылезает
за поля, если не умещается:

```latex
\begin{align*}
  x \in A \cap (B \cup C) &\iff x \in A \land (x \in B \lor x \in C) \\
  &\iff (x \in A \land x \in B) \lor (x \in A \land x \in C) \\
  &\iff x \in (A \cap B) \cup (A \cap C)
\end{align*}
```

`&` перед каждым `\iff` выравнивает их в один столбец — цепочка читается
сверху вниз, шаг за шагом, а не влево-вправо по краю страницы.

Короткую цепочку (сама по себе уместилась бы в одну строку) оставляем
инлайн — `align*` для неё избыточен. Но «сама по себе уместилась бы» не
значит «уместится там, где она оказалась в абзаце»: автоперенос по ширине
всё равно может задеть её произвольно, в том числе посередине одной из
скобочных групп внутри неё (`x \in A \lor x \in` / `X)`). Поэтому каждую
скобочную группу внутри инлайн-цепочки — оборачивать в `\nosplit{...}`
(определён в преамбуле):

```latex
$x \in A \cup X \iff \nosplit{(x \in A \lor x \in X)} \iff x \in X$
```

`\nosplit` не запрещает перенос строки перед `\iff` или после него (это
нормальные, семантически осмысленные точки разрыва — ровно те же, что и
границы `\iff` в `align*` выше) — он запрещает разрыв только внутри самой
скобки, поднимая локально `\relpenalty`/`\binoppenalty` (пенальти за перенос
на `\in`/`\subseteq` и на `\land`/`\lor` внутри группы).

**Не `\mbox`.** Первая версия этого правила использовала `\mbox{$...$}` —
он тоже запрещает перенос внутри скобки, но ценой куда большей: `\mbox`
замораживает ширину группы совершенно жёстко, и это лишает обычную выключку
(и `microtype`) возможности чуть сжать-растянуть соседние пробелы. На
пункте (b) леммы 3.1.13 это дало не «перенос ушёл на другую строку», а
`Overfull hbox` — строка вылезла на ~27pt (почти 1см) за правое поле,
хотя визуально в PDF это было почти незаметно. `\nosplit` не создаёт
жёсткого бокса — обычная выключка вокруг него работает как обычно, TeX
просто не имеет права выбрать перенос СТРОГО внутри скобки.

Если после `\nosplit` строка всё равно получается заметно неровной (широкие
пробелы — TeX не смог красиво выключить строку без внутреннего переноса,
которого мы запретили) — не пытаться исправить это ещё одним LaTeX-трюком,
а просто разбить предложение на два вручную (`\\` в осмысленном месте, до
начала цепочки), чтобы у цепочки была своя строка с запасом по ширине:

```latex
Поскольку $A \subseteq X$, из $x \in A$ следует $x \in X$.\\
Значит $x \in A \cup X \iff \nosplit{(x \in A \lor x \in X)} \iff x \in X$, ...
```

Тот же приём — когда в одном предложении подряд идут ДВЕ независимые
`\nosplit`-цепочки, соединённые союзом («, и», «, и так же»): не оставлять
их одним абзацем (автоперенос всё равно порежет по ширине, не по смыслу),
а разрывать `\\` ровно на этом союзе, так что у каждой цепочки — своя
строка:

```latex
\prooflabel{(b)} Поскольку $A \subseteq X$, из $x \in A$ следует $x \in X$.\\
Значит $x \in A \cup X \iff \nosplit{(x \in A \lor x \in X)} \iff x \in X$,\\
и $x \in A \cap X \iff \nosplit{(x \in A \land x \in X)} \iff x \in A$.

\prooflabel{(c)} $x \in A \cap A \iff \nosplit{(x \in A \land x \in A)} \iff x \in A$,\\
и так же $x \in A \cup A \iff \nosplit{(x \in A \lor x \in A)} \iff x \in A$.
```

(утверждение 3.1.27, пункты (b) и (c)). Признак, что нужен этот разрыв —
не длина цепочек самих по себе, а то, что они СВЯЗАНЫ в одном предложении
и вместе не помещаются в отведённую им строку абзаца.

## Короткие вставки кода в тексте

```latex
конструкторы \code{zero : Nat} и \code{succ : Nat → Nat}
```

`\code` (не `\texttt`/`\path` напрямую) — оборачивает в `\mbox`, чтобы короткий
фрагмент не переносился пополам на границе строки. Не более одной-двух таких
вставок в одном предложении — три и больше визуально дробят фразу, читать
становится тяжело. Если сигнатур/фрагментов больше двух — выносить их в
`itemize`, не перечислять инлайном.

## Короткие математические пометки в скобках

```latex
$P(\Omega)$\mbox{ (берём $X := \Omega$)}, а значит ...
```

Короткая поясняющая вставка в скобках с формулой внутри (`(берём X := Ω)`,
`(здесь n := ...)`) — в `\mbox{...}`, включая открывающую скобку. Без этого
TeX может перенести строку прямо посреди формулы («X :=» на одной строке,
«Ω)» на следующей) — читать такое тяжело, тот же класс проблемы, что и с
`\code`.

## Разбор случаев в доказательстве

```latex
\caselabel{$\Omega \in \Omega$}
Тогда ...
```

вместо ручного `\smallskip\noindent\textbf{Случай ...}`. `\caselabel` (и
`\prooflabel`, см. ниже) сами переносят текст после себя на новую строку —
подпись «Случай ...» никогда не делит строку с началом рассуждения. Без
этого при полной выключке (justification) короткая жирная подпись и
следующие за ней слова иногда попадали на одну строку с нестандартным
набором пробелов, и растяжка межсловных пробелов на этой строке визуально
отличалась от соседних строк.

## Цепочечные доказательства

Если доказательство — короткая цепочка шагов, каждый из которых следует из
предыдущего по одной аксиоме/лемме, каждый шаг — на своей строке через `\\`,
не сплошным абзацем. Само рассуждение — обычным текстом, ссылка на
аксиому/лемму — мелкой серой пометкой через `\by` сразу после утверждения,
а не ведущим «По аксиоме X, ...»: рассуждение должно бросаться в глаза
первым, обоснование — вторично и не должно с ним конкурировать:

```latex
\begin{proof}
$0$ — натуральное число.\by{\taoref{ax:2.1}{аксиома 2.1}}\\
$0{+}{+} = 1$ — натуральное число.\by{\taoref{ax:2.2}{аксиома 2.2}}
\end{proof}
```

Заголовок «Доказательство.» уже сам переносится на новую строку (правка в
преамбуле) — текст доказательства всегда начинать с новой строки, ничего
дополнительно вставлять для этого не нужно. По той же причине формулировка
внутри `axiom`/`theorem`/`proposition`/... тоже сама начинается с новой
строки (свой стиль `tao` в `\newtheoremstyle`, а не встроенный
`definition`) — заголовок «Аксиома 3.8 (...)» никогда не делит строку с
началом формулировки.

Все пронумерованные и звёздные окружения (`axiom`, `theorem*`, ...) сами
запрещают разрыв страницы сразу после себя (`\nopagebreak` в конце) — так
формулировка никогда не остаётся одна на странице, оторванная от
доказательства или замечания, которое сразу за ней следует. Ничего для
этого делать не нужно, это встроено в преамбулу.

## Ссылки на другие аксиомы/теоремы

Каждое пронумерованное окружение (`axiom`, `theorem`, `proposition`, ...)
само ставит метку `префикс:номер` (`ax:2.1`, `prop:2.1.4`, `def:2.1.3`, ...).
Любое упоминание номера в прозе — через `\taoref`, не голым текстом:

```latex
По \taoref{ax:2.1}{аксиоме 2.1}, ...
```

`\taoref` красит текст ссылки в приглушённый синий (`taoblue`) — hyperref
подключён с `[hidelinks]` и сам никак ссылки не выделяет, без цвета ссылку
визуально не отличить от обычного текста и непонятно, что по ней можно
кликнуть.

Так читатель может кликнуть и перейти к формулировке, не держа всё в голове
и не листая книгу руками. Падеж/формулировку текста задаём сами вторым
аргументом — макрос не пытается его угадывать. Список префиксов: `ax`,
`thm`, `prop`, `lem`, `cor`, `def`, `ex`, `exr`, `assum` (все — как имена
соответствующих окружений).

Не годится для доказательств со связной прозой или разбором случаев (там
уже есть `\caselabel`) — только для явных пошаговых цепочек.

## Типографика

- Курсив используется минимально: только для «Доказательство.» (стандарт
  amsthm) и точечных `\emph{}`. Тело теорем/аксиом/замечаний — прямым
  шрифтом (`\theoremstyle{definition}`, не `plain`).
- Кавычки — только литерные `«...»` (Unicode), не `<<...>>`.
- Диапазоны/тире — только литерный `–` (Unicode en dash), не `--`: лигатура
  `--`→`–` не работает для этого шрифтового инстанса под polyglossia (тот же
  класс проблемы, что и с кавычками).
- Документ читается с экрана: `oneside`, широкие поля (2.7см), интерлиньяж
  1.08.
- Служебные пометки (`Lean: ...`) — приглушённый серый (`leangray`), чтобы
  не спорить контрастом с математическим текстом.

## Грабли (см. также комментарии в preamble.tex)

- **`^`/`_` в тексте сигнатуры `\leansource{X}{сигнатура}` ломает сборку** —
  второй аргумент идёт в `\texttt{}` (не `\path`), значит спецсимволы
  (`^`/`_`/`#`/`&`/`%`) нужно экранировать вручную (`\textasciicircum{}`,
  `\_`, ...), как в любом обычном тексте LaTeX — это касается и
  идентификаторов внутри самой сигнатуры (`h_union` → `h\_union`), не
  только первого аргумента `\leansource`.
- **XeLaTeX + polyglossia не видит кириллицу в PT Serif/Menlo автоматически** —
  нужно явно `\newfontfamily\cyrillicfont`/`\cyrillicfonttt`, иначе ошибка
  сборки "does not contain the Cyrillic script".
- **`\url`/`\path` наследуют курсив окружения** (`\urlstyle{same}`, дефолт
  hyperref) — для моноширинного шрифта курсив (синтетический наклон)
  выглядит плохо. Зафиксировано `\urlstyle{tt}` в преамбуле — код всегда
  прямой, независимо от контекста.
- **Длинные Lean-идентификаторы без точек разрыва вылезают за поля**, если
  просто завернуть их в `\texttt{}` — используем `\path`+`xurl` (перенос по
  любому символу) и держим идентификатор вне заголовка окружения (в
  `\leansource`, обычным абзацем, где есть место для переноса).
- **`<<`/`>>` не превращаются в кавычки-ёлочки** под XeLaTeX (это трюк
  pdflatex+babel) — писать `«»` литерально.
- **Menlo при том же кегле визуально крупнее и жирнее PT Serif** — инлайн-код
  «прыгает» на фоне обычного текста. Зафиксировано
  `\setmonofont{Menlo}[Scale=MatchLowercase]` в преамбуле (подгоняет размер
  моно-шрифта по x-height основного) — трогать эту опцию, только если снова
  сменится гарнитура.
- **Короткая вставка кода может перенестись пополам на границе строки**, если
  завернуть её в голый `\texttt{}` — использовать `\code{}` (см. выше), он
  оборачивает в `\mbox`.
- **`--` не превращается в тире `–`** под XeLaTeX+polyglossia (та же природа,
  что и с кавычками — лигатуры `Ligatures=TeX` не подключены для этого
  шрифтового инстанса) — писать `–` литерально.
- **`\path{}` схлопывает пробелы** — годится только для идентификаторов без
  пробелов (`\leanref`/`\leansource`). Для коротких вставок кода с пробелами
  прямо в тексте (`zero : Nat`, `succ : Nat → Nat`) — обычный `\texttt{}`.
- **`\clubpenalty`/`\widowpenalty`/`\interlinepenalty` не спасают от разрыва
  страницы внутри `\raggedright`-абзаца, если внутри него есть `\\`** —
  `\raggedright` переопределяет `\\` на `\@centercr`, а та сама вызывает
  `\par`: то, что выглядит как «вторая строка того же абзаца» (например,
  сигнатура после `\leanbreak` в `\leansource`), на самом деле НОВЫЙ абзац.
  Эти три регистра работают только для разрывов ВНУТРИ одного абзаца — на
  межабзацный разрыв не действуют, сколько их ни выставляй в 10000
  (проверено на минимальном примере). Если блок обязательно должен остаться
  целым — оборачивать в `\parbox` (как в `\leansource`), а не бороться
  penalty-регистрами.
- **`\ ` (обратный слэш + пробел) внутри `\texttt{}`/сигнатуры печатает
  пробел, а не обратный слэш** — это управляющий пробел TeX
  (`\controlspace`), а не литеральный символ. Знак `\` из Lean-синтаксиса
  разности множеств (`X \ Y`) нужно печатать как `\textbackslash{}`, иначе
  он просто исчезает (видно как двойной пробел, «X  Y» вместо «X \ Y»).
